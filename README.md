# LineBot-CRM

ระบบ CRM สำหรับสหกรณ์/องค์กร ผ่าน LINE Official Account

- **Backend**: Google Apps Script (Web App) + Google Sheets เป็นฐานข้อมูล — โฟลเดอร์ `backend/`
- **Frontend**: หน้าเว็บ LIFF โฮสต์ที่ Netlify — โฟลเดอร์ `frontend/`
  - `/` หน้าสมาชิก: ลงทะเบียน, แจ้งเรื่อง, ติดตามเรื่อง, แก้ข้อมูลตัวเอง
  - `/admin/` หน้าเจ้าหน้าที่: ภาพรวม, เรื่องแจ้ง, สมาชิก, ส่งประกาศ, จัดการเจ้าหน้าที่
- **LINE bot**: webhook รับ follow/unfollow และข้อความ ("สถานะ", "แจ้งเรื่อง"), แจ้งเตือนสมาชิก/เจ้าหน้าที่อัตโนมัติ

> หน้า LIFF ต้องโฮสต์นอก Apps Script เสมอ (HtmlService ใช้ iframe ซึ่งทำให้ `liff.init()` พังบน iOS)

## การยืนยันตัวตน

ทุกคำขอส่ง **LINE ID token** (`liff.getIDToken()`) ไป backend แล้ว backend ตรวจกับ LINE (`/oauth2/v2.1/verify`) เอง
ไม่เชื่อ userId ที่ client ส่งมา สิทธิ์แบ่งเป็น user < member (active) < staff < admin

## ติดตั้ง

### 1. LINE Developers
1. ใช้ Messaging API channel ที่มีอยู่ (ตัวเดียวกับที่ `line-bot` MCP ใช้)
2. ใน **Provider เดียวกัน** สร้าง **LINE Login channel** (ให้ userId ตรงกัน) → จด **Channel ID**
3. ใน LINE Login channel → แท็บ LIFF → Add สองตัว (Scope: `profile`, `openid`; Size: Full)
   - สมาชิก: Endpoint URL = `https://<โดเมน netlify>/`
   - เจ้าหน้าที่: Endpoint URL = `https://<โดเมน netlify>/admin/`

### 2. Backend (Apps Script)
```bash
npm i -g @google/clasp
clasp login
cd backend
clasp create --type webapp --title "LineBot-CRM" --rootDir .
clasp push
```
เปิดโปรเจกต์ใน Apps Script → **Project Settings → Script properties** เพิ่ม:

| Key | ค่า |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | Channel access token ของ Messaging API |
| `LINE_LOGIN_CHANNEL_ID` | Channel ID ของ LINE Login channel |
| `WEBHOOK_TOKEN` | สตริงสุ่มยาว ๆ (ตั้งเอง ใช้ป้องกัน webhook ปลอม) |
| `BOOTSTRAP_ADMIN_USER_ID` | LINE userId ของแอดมินคนแรก (ขึ้นต้น `U`) |
| `LIFF_MEMBER_URL` | `https://liff.line.me/<LIFF ID สมาชิก>` |
| `ID_HASH_SALT` | ค่าลับสำหรับแฮชเลขประจำตัวประชาชน สร้างโดย `tools/prepare-import.js` (ดูหัวข้อ "นำเข้าสมาชิก") **ห้ามเปลี่ยนหลังนำเข้าแล้ว** |

จากนั้น:
1. เลือกฟังก์ชัน `setupSchema` แล้ว Run (อนุญาตสิทธิ์) — จะสร้าง Google Sheet ให้และบันทึก `SPREADSHEET_ID` อัตโนมัติ
2. รัน `checkConfig` เพื่อตรวจว่า property ครบ
3. **Deploy → New deployment → Web app** (Execute as: Me, Who has access: Anyone) → คัดลอก URL `/exec`
4. แก้โค้ดภายหลัง: Deploy → Manage deployments → ✏️ → Version: **New version** (ห้ามสร้าง deployment ใหม่ ไม่งั้น URL เปลี่ยน)

### 3. Webhook
ใน Messaging API channel ตั้ง Webhook URL เป็น
`<URL /exec>?wh=<WEBHOOK_TOKEN>` แล้วเปิด "Use webhook" (ปิด auto-reply ของ LINE OA Manager เพื่อไม่ให้ตอบซ้ำ)

> Apps Script อ่าน header ของคำขอไม่ได้ จึงตรวจ `x-line-signature` ไม่ได้ ใช้ `?wh=` ลับแทน

### 4. Frontend
1. แก้ `frontend/assets/config.js` ใส่ `API_BASE` (URL `/exec`), `LIFF_ID_MEMBER`, `LIFF_ID_ADMIN`
2. Deploy โฟลเดอร์ `frontend/` ขึ้น Netlify (publish directory = `frontend`, ไม่ต้อง build) — มี `netlify.toml` ให้แล้ว
3. กลับไปตั้ง Endpoint URL ของ LIFF ทั้งสองตัวให้ตรงโดเมนจริง

## นำเข้าสมาชิกและการลงทะเบียน

สมาชิกลงทะเบียนโดยกรอก **เลขสมาชิก + เลขประจำตัวประชาชน** ระบบจับคู่กับทะเบียนที่นำเข้าไว้ ถ้าตรงจะผูกกับบัญชี LINE และเป็น `active` ทันที
ไม่ตรง = ปฏิเสธ (ไม่สร้างสมาชิกใหม่เอง) กรอกผิดเกิน 5 ครั้งต่อบัญชี LINE (หรือ 10 ครั้งต่อเลขสมาชิก) ล็อก 30 นาที

เลขประจำตัวประชาชนไม่ถูกเก็บใน Sheet/log เก็บเฉพาะ HMAC-SHA256 (คอลัมน์ `IdHash`) และไม่ถูกส่งออกทาง API

1. Export ทะเบียนเดิมเป็น **CSV UTF-8** ไว้ที่ `import/members.csv` (โฟลเดอร์ `import/` อยู่ใน `.gitignore`)
   คอลัมน์ที่ต้องมี: เลขสมาชิก, ชื่อ-นามสกุล, เลขบัตรประชาชน (ไม่บังคับ: โทรศัพท์, กลุ่ม, แท็ก — ดูชื่อหัวคอลัมน์ที่รู้จักใน `ALIASES` ของสคริปต์)
2. รัน `node tools/prepare-import.js import/members.csv` → ได้ `import/members-import.csv` (ไม่มีเลขบัตร ไม่มีแถวหัวตาราง)
   ครั้งแรกสคริปต์สร้าง `ID_HASH_SALT` เก็บใน `.env` → เพิ่มเป็น Script Property ด้วยค่าเดียวกัน (Apps Script → Project Settings)
   สคริปต์รายงานแถวที่มีปัญหาเป็นเลขบรรทัด (เลขบัตรผิด, เลขสมาชิกซ้ำ ฯลฯ) แก้ต้นฉบับแล้วรันใหม่
3. เพิ่มคอลัมน์ `IdHash` ในชีต: `clasp push` แล้วรัน `setupSchema` ซ้ำใน Apps Script
4. เปิดชีต `Members` → File → Import → Upload `members-import.csv` → **Append to current sheet** และ **ยกเลิกติ๊ก "Convert text to numbers, dates, and formulas"** (กันเลข 0 นำหน้าหาย)
5. รัน `verifyImport` ใน Apps Script ต้องได้ "ผ่าน ✅" (ตรวจ hash, เลขสมาชิกซ้ำ, เบอร์โทรที่เลข 0 หาย)
6. **ลบ `import/members.csv` (ต้นฉบับที่มีเลขบัตร)** หลังนำเข้าเสร็จ และเก็บ salt ไว้ที่ที่ปลอดภัย (ทำใหม่ไม่ได้ถ้าหาย ต้องแฮชและนำเข้าใหม่ทั้งหมด)

## จัดการสมาชิก (หน้าเจ้าหน้าที่ → แท็บ "สมาชิก")

- ค้นหา/กรองตามชื่อ เบอร์ เลขสมาชิก สถานะ กลุ่ม แท็ก แบ่งหน้าละ 50 คน
- กดสมาชิกเพื่อแก้สถานะ เลขสมาชิก (ห้ามซ้ำ) กลุ่ม แท็ก หมายเหตุ และดูเรื่องที่เคยแจ้ง
- เลือกหลายคน (ทีละหน้า หรือ "ทั้งหมดที่ตรงตัวกรอง") แล้วเพิ่ม/เอาแท็กออก ย้ายกลุ่ม เปลี่ยนสถานะเป็นใช้งาน/ปิดใช้งาน (ยังไม่ผูก LINE = ตั้งเป็นใช้งานไม่ได้)
- เฉพาะ `admin`: ส่งออก CSV (ไม่มีเลขบัตร/LINE userId, บันทึก `Audit` ทุกครั้ง) และนำเข้ากลุ่ม/แท็กจาก CSV (คอลัมน์ เลขสมาชิก + กลุ่ม/แท็ก) — สมาชิกใหม่ทั้งชุดนำเข้าผ่าน `tools/prepare-import.js` เท่านั้น
- ทุกการแก้ไข/ส่งออกถูกบันทึกในชีต `Audit`

## ส่งประกาศเฉพาะกลุ่ม (แท็บ "ส่งประกาศ", เฉพาะ `admin`)

- เลือกกลุ่ม (dropdown) และ/หรือแท็ก (ติ๊กได้หลายแท็ก, เงื่อนไข "ใดแท็กหนึ่ง" หรือ "ครบทุกแท็ก") — ตัวเลขข้างชื่อคือจำนวนที่ส่งถึงได้จริง
- ส่งถึงเฉพาะสมาชิก `active` ที่ผูก LINE แล้วและยังติดตาม OA "ตรวจจำนวนผู้รับ" แสดงจำนวนที่ถูกตัดออกพร้อมเหตุผล
- "ส่งทดสอบถึงตัวเอง" กิน 1 ข้อความและไม่บันทึกในประวัติ ควรทดสอบก่อนส่งจริงทุกครั้ง
- ระบบตรวจซ้ำก่อนส่ง: จำนวนที่ยืนยันต้องตรงกับที่ส่งจริง, ไม่ให้ส่งข้อความ+กลุ่มเดิมซ้ำภายใน 10 นาที, ไม่ส่งเกินโควตาที่เหลือ

## ตอบอัตโนมัติ (แท็บ "ตอบอัตโนมัติ")

กฎเก็บในชีต `AutoReplies` แก้ได้จากหน้าเจ้าหน้าที่ (เฉพาะ `admin` แก้ได้ เจ้าหน้าที่ทั่วไปดูและทดสอบได้) ตอบผ่าน reply token จึง**ไม่กินโควตาข้อความ**

- วิธีจับคู่: มีคำนี้อยู่ในข้อความ (`contains`, คำต้องยาว ≥ 2 ตัวอักษร) / ตรงทั้งข้อความ (`exact`) / ไม่ตรงกฎใดเลย (`fallback`, มีได้ 1 กฎ)
- ลำดับ: คำสั่งในตัว "สถานะ/ติดตาม" → กฎตามลำดับความสำคัญ (มาก = ก่อน, `exact` ก่อน `contains`) → fallback → ข้อความ default
- ตัวแปรในข้อความตอบ: `{{name}}` ชื่อสมาชิก, `{{link}}` ลิงก์หน้าสมาชิก
- ตอบเฉพาะแชตส่วนตัว ไม่ตอบในกลุ่ม/ห้องแชต ตอบเป็นข้อความตัวอักษรอย่างเดียว
- กฎตั้งต้น 2 ข้อถูกสร้างตอน `setupSchema` (รันซ้ำเพื่อสร้างชีตใหม่นี้หลัง `clasp push`) ใช้ช่อง "ทดสอบข้อความ" ก่อนเปิดกฎใหม่

## Rich menu (สลับตามสถานะ)

ผู้ใช้เห็นเมนูต่างกันตามสถานะ ระบบสลับให้อัตโนมัติ (ไม่กินโควตาข้อความ):

| ผู้ใช้ | เมนู | วิธีที่ได้ |
|---|---|---|
| ยังไม่ลงทะเบียน / ปิดใช้งาน | guest | เมนูเริ่มต้นของ OA (`default`) |
| สมาชิก `active` | member | ผูกรายบุคคลตอนลงทะเบียน/เปลี่ยนสถานะ |
| เจ้าหน้าที่ที่เปิดสิทธิ์ | staff | ผูกรายบุคคลตอนเพิ่มเจ้าหน้าที่ (สำคัญกว่า member) |

1. **สร้างเมนู 3 อัน ผ่าน Messaging API** (เช่น MCP `create_rich_menu`) — เมนูที่สร้างใน LINE OA Manager ผูกรายบุคคลผ่าน API ไม่ได้
   ปุ่มชี้ไป `https://liff.line.me/<LIFF สมาชิก>` และ `https://liff.line.me/<LIFF เจ้าหน้าที่>` หรือส่งข้อความ เช่น "สถานะ"
   ⚠ `create_rich_menu` ตั้งเมนูที่สร้าง**เป็นเมนูเริ่มต้นของ OA ทันที** (ทุกคนเห็น) สร้างเมนู guest เป็นอันสุดท้าย และอย่าสร้างระหว่างช่วงทดสอบที่ยังไม่อยากให้สมาชิกทั่วไปเห็น
2. หน้าเจ้าหน้าที่ → แท็บ **Rich menu** (เฉพาะ `admin`) → เลือกเมนูให้แต่ละบทบาท → บันทึก (เลือก guest = ตั้งเป็นเมนูเริ่มต้นของ OA)
3. กด "ซิงค์เมนูให้ทุกคนตอนนี้" เพื่อผูกเมนูให้สมาชิก/เจ้าหน้าที่ที่มีอยู่แล้ว (หรือรัน `syncAllRichMenus` ใน Apps Script)
- ถ้ายังไม่ตั้งเมนู member/staff ระบบส่วนนี้ไม่ทำอะไร ความล้มเหลวของ LINE API บันทึกใน log เท่านั้น ไม่กระทบการลงทะเบียน/แก้สถานะ
- เปลี่ยนสถานะหลายคนพร้อมกัน เมนูถูกซิงค์ให้เฉพาะคนที่สถานะเปลี่ยน

## สำรองข้อมูลรายวัน

ทุกวัน 02:00 (เวลาไทย) คัดลอกทั้งไฟล์ฐานข้อมูลไปโฟลเดอร์ **LineBot-CRM Backups** ใน Drive ของเจ้าของสคริปต์ เก็บย้อนหลัง 30 วัน
ชุดที่เกินอายุถูกย้ายไปถังขยะของ Drive (กู้คืนได้อีก 30 วัน) และจะเหลือชุดล่าสุดอย่างน้อย 7 ชุดเสมอ กันกรณี trigger หยุดแล้วชุดเก่าถูกลบจนหมด
ล้มเหลวแล้วแจ้งเจ้าหน้าที่ทาง LINE และบันทึกใน `Audit` (การสำรองสำเร็จก็บันทึกเช่นกัน)

**ตั้งค่า (ครั้งเดียว):** หลัง `clasp push` (มีการเพิ่มสิทธิ์ Drive และ Triggers ใน `appsscript.json`) เปิด Apps Script → รัน `installBackupTrigger` → อนุญาตสิทธิ์ใหม่
แล้ว Deploy → Manage deployments → ✏️ → New version (ให้ web app ใช้สิทธิ์ใหม่) จากนั้นรัน `checkBackup` เพื่อตรวจ หรือดูการ์ด "ข้อมูลสำรอง" ในแท็บเจ้าหน้าที่ (มีปุ่ม "สำรองตอนนี้")

**กู้คืน:** เปิดไฟล์สำรองล่าสุดที่ดี ตรวจข้อมูล แล้วเลือกอย่างใดอย่างหนึ่ง
1. ตั้ง Script Property `SPREADSHEET_ID` เป็น ID ของไฟล์สำรอง (เร็วสุด ระบบใช้ไฟล์นั้นต่อทันที) หรือ
2. คัดลอกข้อมูลในแท็บที่เสียกลับไปไฟล์จริง
ตัวนับเลขที่ (`SEQ_*`) อยู่ใน Script Properties ไม่ได้อยู่ในไฟล์สำรอง แต่ไม่กระทบการกู้คืน

⚠ ไฟล์สำรองมีข้อมูลส่วนบุคคลเหมือนไฟล์จริง **ห้ามแชร์โฟลเดอร์สำรอง** และเมื่อย้ายความเป็นเจ้าของระบบไปบัญชีกลางของสหกรณ์ ต้องย้าย/สร้างโฟลเดอร์สำรองใหม่ให้อยู่ในบัญชีนั้นด้วย (ลบ Property `BACKUP_FOLDER_ID` แล้วรัน `backupNow` จะสร้างโฟลเดอร์ใหม่)

## ข้อควรระวัง
- ส่งประกาศกินโควตาข้อความรายเดือนตามจำนวนผู้รับ (แผนปัจจุบัน 60,000/เดือน) UI บังคับให้ยืนยันจำนวนก่อนส่ง และ backend ปฏิเสธถ้าเกินโควตาที่เหลือ
- เฉพาะ `admin` ส่งประกาศและจัดการเจ้าหน้าที่ได้
- ห้าม commit token/secret — เก็บใน Script Properties เท่านั้น
